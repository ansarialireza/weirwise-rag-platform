## 1. Batch Ingestion Envelope (`BehavioralBatchIngestionRequest`)

The outer JSON envelope submitted by the frontend SDK:

```typescript
interface BehavioralBatchIngestionRequest {
  session_id: string;                    // Required: 8-128 chars, client-generated session UUID/token
  workspace_id?: string | null;          // Optional: UUID of active workspace (null for public or global routes)
  device_context?: DeviceContextSchema;  // Optional: Physical and browser runtime geometry
  geographic_context?: GeographicContextSchema; // Optional: Browser-reported timezone and hint
  events: BehavioralEventItem[];         // Required: 1 to 100 atomic interaction events
}
```

### 1.1 Device Context (`DeviceContextSchema`)

| Field | Type | Required? | Allowed Values / Limits | Description | Example |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `device_category` | string | No | `"desktop" \| "laptop" \| "tablet" \| "mobile" \| "unknown"` | Physical form factor | `"desktop"` |
| `operating_system` | string | No | Max 64 chars | Operating system name | `"Windows"` |
| `os_version` | string | No | Max 32 chars | OS release version | `"11"` |
| `browser` | string | No | Max 64 chars | Browser brand name | `"Chrome"` |
| `browser_version` | string | No | Max 32 chars | Browser major version | `"124.0.0.0"` |
| `screen_width` | integer | No | 1 to 10000 | Monitor screen width | `1920` |
| `screen_height` | integer | No | 1 to 10000 | Monitor screen height | `1080` |
| `viewport_width` | integer | No | 1 to 10000 | Browser viewport width | `1440` |
| `viewport_height` | integer | No | 1 to 10000 | Browser viewport height | `900` |
| `device_pixel_ratio` | string | No | Max 16 chars | Display scaling ratio | `"1.25"` |
| `user_agent_normalized` | string | No | Max 255 chars | Sanitized user agent | `"Mozilla/5.0 ..."` |
| `access_environment` | string | No | `"web_app" \| "pwa" \| "embedded_widget" \| "unknown"` | Execution container | `"web_app"` |

### 1.2 Geographic Context (`GeographicContextSchema`)

> [!NOTE]
> The backend derives authenticated geolocation (`country_code`, `country_name`) exclusively from verified Cloudflare headers (`CF-IPCountry`, `CF-RAY`) via `GeoIPService`. The frontend only reports non-identifying client timezone.

| Field | Type | Required? | Allowed Values / Limits | Description | Example |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `timezone` | string | No | Max 50 chars | Client IANA timezone identifier | `"America/New_York"` |

## 2. Canonical Event Item (`BehavioralEventItem`)

The atomic event model ingested into Redis Streams and persisted to `behavioral_events`:

| Field | Type | Required? | Validation Rules | Description |
| :--- | :--- | :--- | :--- | :--- |
| `event_id` | UUID | **Yes** | Standard UUIDv4 string | Unique idempotency key generated by client |
| `category` | string | **Yes** | Enum: `"navigation"`, `"feature"`, `"action"`, `"workflow"`, `"friction"`, `"error"` | Functional domain classification |
| `event_name` | string | **Yes** | Dot-notated string: `^[a-z0-9_]+(\.[a-z0-9_]+)+$` (3-64 chars) | Standardized hierarchical event identifier |
| `component_id` | string | No | Max 128 chars | Stable semantic UI component ID (e.g. `"btn-assistant-save"`) |
| `route` | string | **Yes** | Min 1, Max 255 chars | Active application route (path without query credentials) |
| `referrer_route` | string | No | Max 255 chars | Previous route path before transition |
| `duration_ms` | integer | No | Integer $\ge 0$ and $\le 86,400,000$ (24 hours) | Dwell, action latency, or step elapsed time |
| `timestamp` | ISO 8601 | **Yes** | UTC timestamp with timezone offset (`Z`) | Exact client occurrence time |
| `properties` | Object | No | Max 50 keys; no banned keywords | Bounded, allowlisted event metadata |
| `schema_version` | string | No | Default `"1.0"`, Max 16 chars | Schema contract version |

## 3. Standardized Event Taxonomy

All events use the dot-notation standard: `<domain>.<object>.<action>`.

### 3.1 Category: `navigation`
Captures movement across application routes and viewport presence.

- `navigation.route.viewed`:
  - `route`: Target route (e.g. `/workspaces/ws_1/projects/pr_2/assistants`).
  - `referrer_route`: Previous route.
  - `properties`: `{ "navigation_type": "link_click" | "direct" | "popstate" }`.
- `navigation.dwell.heartbeat`:
  - Periodic active engagement beacon emitted while tab is focused and user is active.
  - `duration_ms`: Duration of active interval (e.g. `30000`).
- `navigation.route.exited`:
  - Emitted when navigating away from a route.
  - `duration_ms`: Total active dwell time on the exited route.

### 3.2 Category: `feature`
Captures engagement with high-level platform capabilities to discover adoption and dormant tools.

- `feature.assistant_builder.opened`: User entered assistant configuration canvas.
- `feature.knowledge_crawler.started`: User initiated website or documentation crawler.
- `feature.rag_playground.prompt_tested`: User executed a query test in the prompt playground.
- `feature.export_widget.configured`: User adjusted embed code or widget settings.

### 3.3 Category: `action`
Captures deliberate, high-value user controls without logging every low-level DOM click.

- `action.button.clicked`:
  - `component_id`: Stable UI identifier (e.g. `"btn_create_source"`, `"btn_publish_assistant"`).
- `action.tab.switched`:
  - `component_id`: `"tab_sources_overview"`.
  - `properties`: `{ "from_tab": "documents", "to_tab": "crawlers" }`.
- `action.modal.opened` / `action.modal.dismissed`:
  - `component_id`: `"modal_delete_assistant"`.

### 3.4 Category: `workflow`
Captures multi-step business funnels (e.g. Assistant Creation, Knowledge Ingestion).

- Standard Lifecycle Events:
  - `workflow.funnel.started`
  - `workflow.step.completed`
  - `workflow.step.failed`
  - `workflow.funnel.completed`
  - `workflow.funnel.abandoned`
- Standard Workflow Identifiers (`workflow_id` in properties):
  - `"wf_create_assistant"`
  - `"wf_upload_documents"`
  - `"wf_configure_provider"`
  - `"wf_embed_widget"`
- Required Workflow Properties:
  - `workflow_id`: Canonical workflow name.
  - `workflow_instance_id`: Unique UUID representing this specific funnel run.
  - `step_name`: Identifier of the current stage (e.g. `"select_model"`, `"attach_sources"`).
  - `step_index`: Zero-indexed integer (`0, 1, 2, ...`).

### 3.5 Category: `friction`
Identifies usability friction, repeated retries, and user struggle.

- `friction.action.retried`: User repeated the same action $\ge 3$ times within 10 seconds.
- `friction.form.validation_failed`: Client-side form validation failed before submission.
  - `properties`: `{ "failed_field": "assistant_name", "error_code": "REQUIRED" }` (Zero field values).
- `friction.operation.aborted`: User cancelled a pending long-running operation.

### 3.6 Category: `error`
Tracks operational or network errors impacting user journeys.

- `error.api.request_failed`:
  - `properties`: `{ "endpoint": "/api/v1/projects", "status_code": 500, "error_type": "SERVER_ERROR" }`.
  - **Exclusion Rule**: No raw response bodies or error stack traces with credentials.

## 5. Schema Versioning & Backward Compatibility

- **Current Version**: `"1.0"`.
- **Schema Evolution Protocol**:
  1. Additive fields in `properties` do not trigger schema version increments.
  2. If an existing required field in `BehavioralEventItem` is renamed or transformed, `schema_version` must be incremented to `"2.0"`.
  3. The backend consumer worker inspects `ev.get("schema_version", "1.0")` and applies corresponding transformation logic before persistence.
